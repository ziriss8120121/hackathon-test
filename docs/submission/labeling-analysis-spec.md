## 3. 対象データ

提出前にTrialが追加された場合は、同じ方針で追加処理する。

## 4. 発言ラベル

全発言を保持し、全発言をLLMによるラベル付け対象とする。1発言に複数ラベルを付与してよい。

取得したい情報は以下。

### `labels[]`：発言行為

- `suspect`：疑い
- `defend`：擁護
- `question`：質問
- `rebut`：反論・異議
- `agree`：同意・追随
- `claim`：役職・情報・判断の主張
- `hypothesis`：仮説・可能性の提示
- `vote_intent`：投票意図の表明
- `other`：上記に該当しない発言

### `mentions[]`：発言対象

誰についての発言か。複数対象を許可する。

### `stances[]`：対象への態度・強度

各スタンスは、対象者、方向、強度を持つ。

- `direction: suspicion`：疑い
- `direction: support`：擁護
- `direction: neutral`：中立
- `direction: unclear`：不明

`strength` は疑い・擁護などの強さを1〜3で扱う。

- 1：可能性の1つとして触れる
- 2：理由を挙げて立場を示す
- 3：断定に近い

### `change_type`：議論上の状態

- `new`：新しい疑い・論点を提示
- `maintain`：既存の疑い・論点を維持
- `change`：疑い先・判断・主張を変更
- `withdraw`：疑い・主張を撤回
- `none`：該当なし

### `evidence_basis[]`：根拠

疑い・擁護・役職主張などの理由が発言から読み取れる場合に付与する。複数可とする。

- `role_information`：役職主張や取得情報に基づく
- `logical_consistency`：発言の矛盾・整合性・推論に基づく
- `behavioral_impression`：態度・発言量・言い回しなどの印象に基づく
- `social_alignment`：他者への同意や多数意見に基づく
- `speculation`：明確な根拠のない可能性の提示
- `unclear`：根拠を特定できない

根拠を無理に推測せず、判断できない場合は`unclear`とする。

### `claim_type` / `claim_content`：主張

`claim_type` は以下から選択する。複数の主張を含む場合は複数可とする。

- `role`：自分または他者の役職に関する主張
- `information`：取得した情報に関する主張
- `judgment`：自分または他者の判断に関する主張
- `vote`：投票意図に関する主張
- `none`：該当なし

`claim_content` には、発言者が何を主張したかを記録する。

## 5. 既存データとの突合

発言ラベル付け時には、役職・MBTI・勝敗などの正解情報を判断材料にしない。

分析時に、発言中の主張を以下の実験データと突合する。

- 真の役職
- 実際に取得していた情報
- プレディスカッション判断
- 投票前判断
- 実際の投票
- 追放結果
- 勝敗

「意図的な嘘」とは判定しない。事実と一致した主張、事実と異なる主張、判定不能な主張として扱えるようにする。

## 7. 実装上の優先順位

1. 既存データを使ったP0の集計
2. 全発言の保持
3. P1の発言ラベル取得
4. P1を使った結果の説明・探索

提出までの時間を優先し、P0を壊さない範囲でP1を実装する。ラベルの具体的な形式、処理方法、保存方法、再実行方法はエンジニア判断とする。

## 8. 完了条件

- 現在の全Trial・全Caseを対象に処理できる
- 各発言がTrial・Case・Playerに紐づいている
- 1発言に複数ラベルを付与できる
- ラベル付けが難しい発言も削除せず保持できる
- P0の既存指標を集計できる
- 発言中の主張を、分析時に正解データと突合できる
- 追加Trialにも同じ処理を適用できる
