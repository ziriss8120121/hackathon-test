### 0.1 本書の位置づけ

| 文書 | 答えること | 例 |
| --- | --- | --- |
| 要求定義書 | なぜ作るか、何がほしいか | MBTI構成だけを変えた比較実験の結果がほしい |
| **要件定義書（本書）** | **システムは何を満たすべきか** | **1 Trialの17ケースを、MBTI構成以外を固定して完走し、指定の項目を記録する** |

### 0.2 上位文書の未決事項の扱い

要求定義書8.5と9.5には未決の条件がある。本書では、要件として固定する範囲と設計書へ委ねる範囲を次のように分ける。

| 上位文書の未決事項 | 本書での扱い |
| --- | --- |
| 100人プールのMBTI・年齢・性別の人数構成と根拠資料 | 構成の値は要件にしない。「人数構成を設定として外部から与え、使用した構成を記録できる」ことを要件にする（F-02、F-04）。 |
| 8人の選び方と同じパターンを再利用するか | 選定方式を設定で切り替えられることと、選定方式・seed・パターンIDを記録することを要件にする（F-05、F-06）。 |
| 議論の終了条件、総発言量の上限、1発言の上限 | 値は要件にしない。「全ケースへ同じ終了条件と上限を適用し、使用した値を記録できる」ことを要件にする（F-22、F-23）。 |
| 固定して使うモデル、基本指示、人格プロンプト、Judge評価基準の各バージョン | 値は要件にしない。識別情報を記録し、Trial内で一致することを要件にする（F-07、F-16）。 |
| 機械可読データのschema、ファイル構成、命名規則 | 設計書で確定する。本書は必須項目だけを定める（4章）。 |
| Judgeの発言ラベル、公開スタンス、強度の定義 | 設計書で確定する。本書はJudgeが満たすべき性質だけを定める（F-40〜F-45）。 |
| 正確性、収束、判断修正の具体的な指標と統計方法 | 設計書で確定する。本書は分析が答えるべき問いだけを定める（F-63、F-64）。 |
| 分析結果を表示する画面構成 | 設計書で確定する。本書は表示すべき内容だけを定める（F-70〜F-76）。 |
| 大量の生データの保存方法と公開方法 | 設計書で確定する。本書はデータ量に関する非機能要件を定める（NF-12）。 |

### 0.3 本書で決めないこと（設計書に委ねる）

- ゲームルールの各役職処理の具体的な手順と、ルール記述の持ち方
- 自由議論で次の発言者を決める具体的な方式
- 個別判断の質問文と自信度の尺度
- Judgeの実装方式、プロンプト、ラベル定義
- 各ファイルのschema詳細、ディレクトリ構成、命名規則
- 操作画面と結果ビューの実装方式、画面レイアウト
- 正確性・収束・判断修正の算出式と統計手法
- 実行の並列化・分散の方式

## 1. システム概要

| 項目 | 内容 |
| --- | --- |
| システム名 | MBTI人狼シミュレーター（研究実験用） |
| 種別 | AIエージェント同士のワンナイト人狼を自動実行し、記録・事後評価・分析を行う実験システム。プレイヤーは全員AIエージェントであり、人間は実行と観察のみを行う。 |
| 研究対象 | MBTI人格条件を与えられたAIエージェント集団の意思決定。実在人物の診断・評価は行わない。 |
| 会話の見え方 | エージェントの発言を生成しながら逐次表示するリアルタイム表示は行わない。実行完了後にまとめて表示する。 |
| 利用者 | チーム3人。実行はしらまゆ（実行担当）またはEngineer、結果閲覧は全員。 |
| 動作単位 | 1ケース = 1ゲーム。1 Trial = 17ケース。1実験 = 複数Trial（目標100 Trial、全1,700ケース）。 |
| 中核処理 | MBTI人格条件を与えた8人のAIエージェントが、ルールに基づく開始時処理、自由議論、投票を行い、勝敗が決まる。議論前と投票直前には非公開の個別判断を取得する。 |
| 事後処理 | ゲーム終了後、発言者とは別のJudgeが会話を発言単位で評価する。 |
| 分析単位 | ケース、Trial、実験全体、RQ1、RQ2。 |

### 1.1 用語

| 用語 | 定義 |
| --- | --- |
| 実験（experiment） | 複数Trialをまとめた実行単位。`experiment_id` で識別する。 |
| Trial | 人物・年齢・性別・開始時役割・ゲーム条件・議論条件を共有する17ケースの組。`trial_id` で識別する。 |
| ケース（case） | 1ゲームの実行単位。`case_id` で識別する。v1.2の `run` に相当する。 |
| 構成種別 | ケースのMBTI条件の種類。混合構成（mixed）または同質構成（homogeneous）。 |
| 混合構成 | 選ばれた8人が人物プールで持つMBTIをそのまま使う1ケース。 |
| 同質構成 | 8人全員のMBTIを同じ1タイプへ変更したケース。16タイプを各1ケース実行する。 |
| 人物（person） | 人物プールの1件。人物ID、MBTI、年齢、性別を持つ仮想人物。 |
| 人物プール | 実験で使用する仮想人物の集合（100人）。 |
| パターン（pattern） | 人物プールから選んだ8人の組み合わせ。`pattern_id` で識別する。 |
| 役割（role） | ゲーム上の役職。人狼、占い師、怪盗、村人。 |
| 開始時役割 | ゲーム開始時に割り当てた役割。Trial内で固定する。 |
| 最終役割 | 役職行動による交換を反映した、勝敗判定に使う役割。ケースごとの結果として記録する。 |
| ルールセット | ゲームルール文書の内容をシステムが実行できる形にしたもの。バージョンで識別する。 |
| 自由議論 | 個人の発言順・発言回数を事前に固定しない公開議論。 |
| 個別判断 | 各プレイヤー本人から取得する非公開の回答。議論前と投票直前の2時点で取得する。 |
| 公開スタンス | Judgeが発言から判定した、そのプレイヤーが公開の場で示している疑いの対象と強さ。 |
| Judge | ゲーム終了後に会話を発言単位で評価する、プレイヤーとは別のAI。ゲーム中の発言には介入しない。 |
| 脳（エージェント脳） | 発言・判断・投票を生成する推論部分。モデルまたは実行方式を指す。 |
| 操作画面 | 実験条件を設定して実行を開始し、進行と結果を確認する画面。ローカルで起動して使う。 |
| 結果ビュー | 実行結果と分析結果だけを表示する静的な画面。実行環境を持たないメンバーがブラウザで開いて使う。 |

## 2. 前提条件・制約条件

### 2.1 コスト制約（最重要）

本システムは、**開発から実行までのすべてを無料の技術スタックで成立させる**ことを絶対要件とする。v1.2から変更しない。

| 区分 | 要件 |
| --- | --- |
| 推論（エージェント脳、Judge） | 無料枠のAPIまたはローカル実行のみを使用する。従量課金APIを前提とした構成は認めない。 |
| ライブラリ・SDK | 無料で利用できるものに限る（OSSまたは無償利用可能なもの）。有償ライセンスを必要としない。 |
| 実行環境 | メンバーが所有するMacのみ。有料のクラウド計算資源は使用しない。 |
| ホスティング・共有 | GitHubおよびGitHub Pagesの無料枠に収める。 |
| CI（使用する場合） | GitHub Actionsの無料枠に収める。無料枠を超える構成は組まない。 |
| 判定 | 課金が発生しうる構成は、採用前に却下する。判断が付かない場合は使用しない。 |

### 2.2 実行規模の制約（v2.0で追加）

全1,700ケースは、1ケースあたりの推論呼び出し回数と1回あたりの待機時間の積で所要時間が決まる。v1.2の実測では、実行時間のほぼすべてがAI応答待ちだった（10試合4,112.731秒のうち4,111.853秒）。

| 区分 | 前提 |
| --- | --- |
| 支配要因 | 所要時間はAI応答待ちが支配する。進行処理の最適化では短縮できない。 |
| 規模の扱い | 100 Trialは目標値であり、実行可否は実測後に判断する。段階的に実行し、実測値から残りの規模を決める。 |
| 上限の必要性 | 自由議論は発言回数が事前に決まらないため、上限を持たない構成では1ケースの所要時間が予測できない。上限の設定を要件とする（F-23）。 |
| 分割実行 | 実験は途中で止まる前提とする。完了済みケースを失わず、未完了ケースから再開できることを要件とする（F-53）。 |
| Judgeの分離 | Judgeの評価はゲーム実行と同時に行う必要がない。ゲーム実行と分けて実行できることを要件とする（F-41）。 |

具体的な呼び出し回数の試算、段階実行の刻み、分散実行の方式は設計書で定める。

### 2.3 その他の前提

| 区分 | 前提 |
| --- | --- |
| 実行方式 | 操作画面からの起動と、コマンドからの起動の両方に対応する。実行開始後は自動進行し、途中で人の入力を必要としない。 |
| 会話の表示 | 実行完了後にまとめて表示する。1発言ずつ流すライブ表示は行わない。 |
| 実行PC | Apple Silicon Mac（M2 MacBook Air / MacBook Pro M3 18GB / Mac mini M4 16GB / MacBook M4 16GB）。 |
| 長時間実行 | Mac mini M4での夜間長時間実行を想定に含める。長時間実行は画面を開いたままにせずコマンドから起動できるようにする。 |
| ゲーム間記憶 | 使用しない。各ケースを独立したゲームとして実行する。 |
| ゲームルール | チーム管理のゲームルール文書に従う。ルール文書が未確定の範囲は、設計書で仮置きとして明示し、確定後に差分を反映する。 |
| 目的 | MBTI理論や心理機能理論の正しさの証明ではなく、MBTI構成を変えた場合の集団意思決定の差の観察。 |
| 正本 | 仕様の正本はConfluence。変更は文書に反映してから実装する。 |

## 3. 機能要件

### 3.1 人物・実験条件の管理

上位: FR-01〜FR-04。課題: A2、A3、A4。

| ID | 要件 | 優先度 | 検証方法 |
| --- | --- | --- | --- |
| F-01 | 仮想人物100人について、人物ID、MBTI、年齢、性別を管理し、一意に識別できる。 | Must | 人物プールの件数が100件で、人物IDが重複せず、各人物の4項目が確認できる。 |
| F-02 | 人物プールを、MBTI・年齢・性別の人数構成を指定して生成できる。MBTIと年齢・性別はランダムに対応付ける。 | Must | 指定した人数構成どおりのプールが生成され、対応付けの方式とseedが記録される。 |
| F-03 | 生成した人物プールを保存し、以後の実験で同じプールを再利用できる。 | Must | 保存済みプールを指定して実験を実行でき、使用したプールの識別情報が記録される。 |
| F-04 | 人物プールの生成に使った人数構成と根拠の識別情報を記録できる。 | Must | プールに人数構成と識別情報が保存されている。 |
| F-05 | 役職構成を人狼2人、占い師1人、怪盗1人、村人4人とし、各役割を一意に識別して8人へ割り当てられる。 | Must | 役割ごとの人数が構成どおりで、役割IDと割当対象の人物IDが確認できる。 |
| F-06 | 人物プールから選んだ8人の組み合わせをパターンとして識別し、パターンIDから8人の人物IDを引ける。 | Must | パターンIDを指定して8人を特定でき、Trialへ関連付けられる。 |
| F-07 | 実験に使用するルールセット、人格プロンプト、Judge評価基準、モデル、基本指示を識別できる。 | Must | 各Trialおよびケースから、使用した各バージョンまたは識別情報を確認できる。 |
| F-08 | 人物の選定と役割の割当にランダム処理を使う場合、方式とseedを記録する。 | Must | 記録された方式とseedから同じ選定・割当を再現できる。 |
| F-09 | 人物プール、役割、パターンを、実験の実行結果とは別のデータとして保存する。 | Must | 実験結果を削除してもプール・パターンの定義が残る。 |

### 3.2 Trial生成とゲーム進行

上位: FR-10〜FR-14、FR-19。課題: A1、A2、A3。

| ID | 要件 | 優先度 | 検証方法 |
| --- | --- | --- | --- |
| F-10 | 1 Trialについて、混合構成1ケースと同質構成16ケースの全17ケースを生成できる。 | Must | 17ケースが同じ `trial_id` へ関連付けられ、各ケースの構成種別とMBTI条件が識別できる。 |
| F-11 | 同一Trial内では、人物ID、年齢、性別、開始時役割、ルールセット、議論条件、モデル、基本指示、人格プロンプト版、Judge評価基準版を固定する。 | Must | 17ケースの条件を比較し、MBTI構成以外がすべて一致している。 |
| F-12 | 同一Trial内で変更するのは、8人へ与えるMBTI条件だけとする。 | Must | 混合構成は人物プールのMBTI、同質構成は8人全員が同一タイプになっている。 |
| F-13 | 各ケースを独立したゲームとして実行し、他のケースやTrialの会話・判断をエージェントへ引き継がない。 | Must | エージェントへの入力に過去ゲームの情報が含まれない。 |
| F-14 | ルールセットに従い、8人のAIエージェントだけでゲーム開始から投票・勝敗判定まで、人の介入なしに進行できる。 | Must | 1ケースの実行操作で結果ファイルが揃い、適用したルールセットの識別情報が記録される。 |
| F-15 | ルールで定めた開始時の情報付与と役職処理を実行し、その結果を記録する。 | Must | 各役職の処理内容と結果、および最終役割が記録されている。 |
| F-16 | 各エージェントへ、本人の人物属性、MBTI人格設定、本人の役割、ルール上取得できる情報だけを与える。 | Must | 他者のMBTIやルール上知り得ない秘密情報が本人への入力に含まれない。他者の年齢・性別は含まれる。 |
| F-17 | 他プレイヤーのMBTIラベルは、ゲーム中のどのエージェントへも開示しない。 | Must | エージェントへの入力文字列に他者のMBTIラベルが出現しない。 |
| F-18 | 投票を行い、ルールに従って追放対象と勝敗を判定する。同数得票時の決着方法を定め、常にケースが終了する状態にする。 | Must | 同数ケースでもケースが終了し、決着方法が記録から判別できる。 |
| F-19 | 勝敗が判定できない場合を「無効」として記録できる。 | Must | 無効となったケースが、勝敗ありのケースと区別して集計から除外できる。 |

### 3.3 自由議論と個別判断

上位: FR-15〜FR-19。課題: A5、A6。

| ID | 要件 | 優先度 | 検証方法 |
| --- | --- | --- | --- |
| F-20 | 公開議論では、個人の発言順と発言回数を事前に固定しない。 | Must | 実行前の設定に個人別の発言順・発言回数の指定が存在しない。 |
| F-21 | 各エージェントが会話状況に応じて発言するかどうかを判断できる。 | Must | 発言せずに見送った記録が残り、プレイヤー間で発言回数が一致しない実行例が得られる。 |
| F-22 | 実際に生じた発言順と発言回数を結果として記録する。 | Must | 全発言の順序と発言者、およびプレイヤー別の発言回数が確認できる。 |
| F-23 | 議論全体の終了条件と上限（総発言量、1発言の長さを含む）を全ケースへ共通に適用し、使用した値を記録する。 | Must | 使用した終了条件と上限が記録され、上限超過なしで議論が終了する。 |
| F-24 | 公開議論の開始前に、各プレイヤーから非公開の初期判断を取得する。項目は本人の役割・取得情報の認識、疑っている人物または判断不能、自信度、理由とする。 | Must | 8人分の初期判断が本人へ紐づいて記録されている。 |
| F-25 | 公開議論後・投票直前に、各プレイヤーから非公開の最終判断を取得する。項目は最も疑っている人物、自信度、理由、投票予定先とする。 | Must | 8人分の最終判断が本人へ紐づいて記録されている。 |
| F-26 | 個別判断の内容は他のプレイヤーへ開示せず、公開議論の入力にも含めない。 | Must | 他プレイヤーへの入力文字列に他者の個別判断が出現しない。 |
| F-27 | 最終判断を取得した後に実際の投票を行い、投票先を投票予定先と区別して記録する。 | Must | 投票予定先と実際の投票先が別項目として記録され、一致・不一致を集計できる。 |
| F-28 | 発言ごとの非公開心理状態は取得しない。 | Must | 個別判断の取得時点が議論前と投票直前の2時点だけである。 |
| F-29 | 脳の応答が想定形式から外れた場合も、ケースを中断させず処理を継続し、事象を記録する。 | Must | 異常応答を含む実行でもケースが完走し、該当箇所が記録から判別できる。 |

### 3.4 記録

上位: FR-20、FR-21、FR-23、FR-25。課題: A2、A5、A6。

| ID | 要件 | 優先度 | 検証方法 |
| --- | --- | --- | --- |
| F-30 | 1ケース分の全データを機械可読なログとして出力する。 | Must | ファイルが生成され、4.2の必須項目を満たす。 |
| F-31 | 公開会話を、発言順が分かる全文Transcriptとして保存する。全発言についてケース、発言者、順序、本文を確認できる。 | Must | 発言の欠落がなく、順序が一意に決まる。 |
| F-32 | 個別判断、開始時の役職処理、投票、追放結果、勝敗または無効、正答・誤答、発言数、発言量を保存する。 | Must | ケースおよびプレイヤー単位で判断変化と結果を追跡できる。 |
| F-33 | 非公開の個別判断と、会話から得た公開スタンスを、別の項目として保存する。上書きしない。 | Must | 内部判断と公開スタンスを別々に取得・分析できる。 |
| F-34 | ケースの時間情報を記録する。開始時刻、終了時刻、所要時間、AI応答待ち時間を対象とする。 | Must | 各値が記録され、待機時間と進行処理の切り分けができる。 |
| F-35 | 実行環境（実行したPCの識別名）と使用モデルをケースごとに記録する。 | Must | 記録から、どのPCとモデルで実行した結果かを特定できる。 |
| F-36 | 人物、役割、パターン、Trial、ケース、発言、個別判断、投票、結果、および適用した各バージョンを相互に追跡できる。 | Must | 分析結果から根拠となるケース・発言・回答まで遡れる。 |
| F-37 | 出力データにschemaのバージョンを持たせ、schema変更後も過去の実行結果を読み分けられる。 | Must | 異なるschemaバージョンの結果が混在しても集計対象を判別できる。 |
| F-38 | 実行が途中で失敗した場合も、その時点までの記録と失敗事象を残す。 | Must | 失敗ケースに部分データと失敗情報が残る。 |
| F-39 | 生データ、事後評価、分析結果を区別して保存する。 | Must | 事後評価や分析をやり直しても生データが変わらない。 |

## 4. データ要件

出力の正本はケース単位の機械可読ログとし、他の出力はそこから導出できる状態にする。schemaの詳細、ファイル名、命名規則は設計書で定める。

### 4.1 マスタデータの必須項目

| 区分 | 必須項目 |
| --- | --- |
| 人物 | 人物ID、MBTI、年齢、性別 |
| 人物プール | プールID、件数、MBTI・年齢・性別の人数構成、生成方式、seed、根拠の識別情報 |
| 役割 | 役割ID、役割種別（人狼 / 占い師 / 怪盗 / 村人）、構成人数 |
| パターン | パターンID、所属する8人の人物ID、選定方式、seed |
| ルールセット | ルールセットID、バージョン、参照元のゲームルール文書の識別情報 |

### 4.2 ケース単位の必須項目

| 区分 | 必須項目 |
| --- | --- |
| 識別情報 | 実験ID、Trial ID、ケースID、構成種別、同質構成の対象タイプ、プールID、パターンID |
| 使用条件 | ルールセット版、モデル、基本指示版、人格プロンプト版、Judge評価基準版、schema版、議論の終了条件と上限、seed |
| 人物・役割 | 人物ID、年齢、性別、ケースで与えたMBTI、開始時役割、最終役割 |
| 開始時処理 | 各役職の処理内容と結果（誰が誰を対象にし、何を得たか） |
| 議論前の個別判断 | 役割・取得情報の認識、疑っている人物または判断不能、自信度、理由 |
| 公開議論 | 発言ID、発言順、発言者、発言本文、発言を見送った記録、形式崩れの有無 |
| 投票前の個別判断 | 最も疑っている人物、自信度、理由、投票予定先 |
| 投票・結果 | 実際の投票先と理由、得票集計、同数時の決着方法、追放対象、勝敗または無効、正答・誤答 |
| 実行状態 | 開始時刻、終了時刻、所要時間、AI応答待ち時間、推論呼び出し回数、状態（完了 / 失敗 / 中断 / 除外）、エラー種別と理由、実行環境 |

### 4.3 Judge評価の必須項目

| 区分 | 必須項目 |
| --- | --- |
| 識別情報 | ケースID、Judgeの識別情報、評価基準版、評価実行時刻 |
| 発言単位の評価 | 対象の発言ID、発言ラベル、言及対象のプレイヤー、公開スタンス（対象と強さ） |
| 導出データ | 時点ごとの公開スタンス系列、時点ごとの疑念分布 |

### 4.4 Trial・実験単位の必須項目

| 区分 | 必須項目 |
| --- | --- |
| Trial | Trial ID、パターンID、開始時役割の割当、固定した条件一覧、17ケースのIDと状態 |
| 実験 | 実験ID、プールID、Trial数、TrialのIDと状態、実行数、有効数、欠損・除外の件数と理由、各バージョン |

### 4.5 確実に取得する指標

プレイヤー別の発言回数、平均発言文字数、発言を見送った回数、投票予定先、実際の投票先、疑い先の変化（議論前→投票前）、自信度の変化、勝敗、正答・誤答。ケース別の総発言数、追放対象、同数得票の有無、所要時間、AI応答待ち時間、推論呼び出し回数。

### 4.6 分析で算出する指標

正確性、意見の収束、判断の変化を表す指標。具体的な算出式、集計単位、統計手法は設計書で定める。指標の定義とバージョンを記録し、変更時は区別できるようにする（F-65）。

### 4.7 機械可読データの粒度

| 粒度 | 用途 |
| --- | --- |
| 1行 = 1プレイヤー × 1ケース | プレイヤー単位の発言量、判断変化、勝敗の集計 |
| 1行 = 1ケース | 構成種別別、タイプ別の集計とRQ分析 |
| 1行 = 1発言 | Judge評価と公開スタンスの再集計 |

各粒度の列構成は設計書で定める。

## 9. リスクと対応方針

| リスク | 影響 | 対応方針 |
| --- | --- | --- |
| 全1,700ケースの所要時間が現実的でない | 実験が完了しない | 段階実行で実測し、規模を判断する（NF-08、AC-21）。議論の上限で1ケースの上限時間を確定させる（F-23）。 |
| 自由議論で発言が発散し、1ケースが終わらない | 実行が予測できない | 終了条件と上限を必須にする（F-23）。上限に達した場合も記録して終了させる。 |
| 自由議論で誰も発言せず、議論が成立しない | 比較データにならない | 発言を見送った記録を残し（F-21、F-22）、成立しなかったケースを欠損・除外として区別する（F-51）。 |
| Judgeの評価がぶれて集計できない | 分析の信頼性が落ちる | 評価基準をバージョン管理し、旧評価を残す（F-42、F-45）。評価はゲームと分けて再実行できるようにする（F-41）。 |
| 人格プロンプトがJudgeの判定語を強制してしまう | 性格差と指示追従が区別できない | 人格プロンプトと評価基準を分離し、判定語の一致を確認する（F-46）。操作確認を別出力にする（F-47）。 |
| 小型モデルで8人分の自由議論と個別判断が成立しない | 観察価値が下がる | 1 Trialで成立を確認し、成立しない場合は推論手段またはプロンプト版を変更して再実行する（F-58、NF-10）。 |
| 応答形式が安定せず集計できない | 集計できない | 想定外応答でも継続する（F-29）。集計に必要な項目は形式を検証する。 |
| 途中中断でTrialの17ケースの組が崩れる | 対応あり比較ができない | ケース単位の状態を記録し、未完了から再開する（F-51〜F-53）。欠損Trialを分析対象から除外できるようにする（F-51）。 |
| 出力が増えてリポジトリが重くなる | 運用が破綻する | 1 Trialで容量を実測し、共有対象と除外対象を分ける（NF-12、F-78、IF-05）。 |
| Trial内の条件固定が実装のミスで崩れる | 研究結果が無効になる | 条件一致を自動検査する（NF-06、AC-02）。 |
| 画面と分析の作り込みに時間を取られ、実験本体が進まない | 実験が遅れる | ゲーム実行、Judge、分析、画面を独立に起動できる構成にし（IF-09）、実行を先に進められるようにする。 |
| ゲームルール文書が未確定のまま実装が進む | 後から作り直しになる | ルールセットをバージョン管理し、仮置き範囲を設計書に明示する（NF-11、2.3）。 |

## 10. スコープ外

- MBTI理論または心理機能理論そのものの正しさを検証すること。
- 実在人物のタイプ診断、評価、ラベリング。
- AIエージェントの結果を人間の集団や組織へ直接当てはめること。
- 特定タイプが常に優れているという結論を出すこと。
- エージェントの発言を生成しながら1発言ずつ流すリアルタイム表示。会話は実行完了後にまとめて表示する。
- 人間が遊べる人狼ゲーム。プレイヤーは全員AIエージェントとする。
- 発言ごとの非公開心理状態の取得。
- ゲーム間記憶（過去ケースの情報をエージェントへ渡すこと）。
- 従量課金APIを前提とした構成、および有料サービスの利用。
- 本番テーマとしてMBTI人狼を採用する前提で進めること。
